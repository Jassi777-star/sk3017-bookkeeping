# AI 协作记录

## AI-01｜需求边界整理

**意图**：把题库题目转成可实现、可验收的课程项目范围。  
**提示词**：根据题目三要求和课程评分标准，整理 Must、Should 和不做项，并明确单用户 MVP。  
**AI 回复摘要**：提出 Flask、MySQL、ECharts、收入支出 CRUD、组合筛选、三类图表和过程材料要求。  
**我的修改/采纳**：采纳单用户和图表方案，保留预算提醒为后置功能，避免增加登录与多账本。

## AI-02｜分类与交易 TDD

**意图**：先锁定分类创建和交易新增的公开行为。  
**提示词**：为 Flask test client 写最小测试，覆盖分类创建、合法支出、负金额和分类类型不一致。  
**AI 回复摘要**：给出 HTTP 行为测试和最小模型、路由实现。  
**我的修改/采纳**：采用 Decimal、服务端校验和 302 重定向，不测试私有解析函数。

## AI-03｜组合筛选与安全删除

**意图**：完成月份、类型、分类组合筛选并保证删除只能 POST。  
**提示词**：按 TDD 扩展交易测试，再实现分页、筛选条件和删除方法限制。  
**AI 回复摘要**：建议使用 ORM 参数绑定、左闭右开月份区间和 Flask-SQLAlchemy 分页。  
**我的修改/采纳**：采纳筛选和分页；把月份边界提取为独立服务，供统计接口复用。

## AI-04｜服务端聚合与图表接口

**意图**：确保三类图表由 MySQL/SQL 聚合，而不是前端计算。  
**提示词**：为分类占比、近 6 个月收支、每日支出写契约测试，并实现缺失月份、缺失日期补零。  
**AI 回复摘要**：给出 `GROUP BY` 聚合、月份序列和完整日期序列方案。  
**我的修改/采纳**：采纳服务端补零和严格月份参数校验，前端只渲染 JSON。

## AI-05｜MySQL 与本地可运行性权衡

**意图**：在不知道本机 MySQL root 密码的情况下仍提供可运行 MVP，同时不放弃课程要求的 MySQL。  
**提示词**：如何让 Flask 项目立即运行，又保留 MySQL 正式配置和建表脚本。  
**AI 回复摘要**：使用 `DATABASE_URL` 切换数据库，本地默认 SQLite，MySQL 8 使用 PyMySQL 和独立 schema。  
**我的修改/采纳**：采纳零配置 SQLite 回退和 MySQL 正式路径；README 明确 SQLite 仅用于 MVP 快速体验。

## AI-06｜高 Star UI 参考筛选

**意图**：找到视觉成熟且适合单页 Flask 应用参考的 GitHub 项目。  
**提示词**：检索个人财务和后台仪表盘项目，比较 star、许可证、信息架构和与本项目的适配度。  
**AI 回复摘要**：推荐 Maybe、Actual Budget、Tabler 和 Gentelella，分别覆盖财务信息、交易体验和后台壳层。  
**我的修改/采纳**：只借鉴布局和视觉原则，不复制源码；继续使用本地 CSS、Jinja 和 ECharts，避免引入 React 或模板依赖。

## AI-07｜预算提醒 TDD

**意图**：按需求文档补齐月度预算和 80% 提醒，同时保证已用支出不可由前端伪造。  
**提示词**：先写预算创建、更新、负金额校验和状态 API 测试，再实现最小预算模型与页面。  
**AI 回复摘要**：建议预算按月唯一存储，已用支出从交易表聚合，API 统一返回进度和提醒状态。  
**我的修改/采纳**：采纳唯一月份和数据库聚合；前端只渲染状态，并通过浏览器实际提交预算完成验收。

## AI-08｜现代化财务界面重构

**意图**：解决传统后台模板感过重的问题，在不引入 React 的前提下提升界面时尚度和移动端可用性。

**提示词**：检索近年的高 star UI 项目，提炼适合 Flask/Jinja 财务应用的布局、图标、卡片和响应式表格模式。

**AI 回复摘要**：推荐参考 shadcn/ui、daisyUI、Midday、Tabler 和 Lucide，并建议使用窄图标侧栏、深色重点指标卡和移动端信息行。

**我的修改/采纳**：采纳视觉结构，使用本地 CSS 和 Lucide 实现；没有引入前端框架，也没有复制 AGPL 项目代码，并通过 Playwright 验证图标、图表和响应式布局。

## AI-09｜最终需求审计与 MySQL 验证

**意图**：按课程评分标准检查最终项目，补齐边界测试和 MySQL 实际运行证据。

**提示词**：逐项核对题目三、需求文档和仓库结构，找出与文档不一致的行为，并为跨月、空月份、闰年和预算临界点增加测试。

**AI 回复摘要**：发现交易列表默认月份和预算阈值舍入问题，建议补充 1-2 页设计文档，并启动独立 MySQL 实例验证 schema、seed 和统计接口。

**我的修改/采纳**：修复两个行为缺陷，把测试扩展到 25 项；新增 `docs/DESIGN.md`；在临时 MySQL 8.0.46 中实际导入 11 个分类和 60 条交易，页面及三类统计接口均通过。
